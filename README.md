# SRW A Portable Plus 1.2 → 한글판 v2.4 이식

밸런스 패치 **Super Robot Wars A Portable Plus v1.2** (Super Rebalance Wars Team)
를 **한글패치 v2.4** ISO 에 이식한다.

원본 `APP 1_2.ppf` 는 영문 *Steel Soul* 번역판 ISO 기준의 raw 오프셋 diff 다.
게다가 PPF 헤더의 `blockcheck = 0` 이라 **대상 파일을 검사하지 않고 무조건 쓴다.**
한글판에 그대로 적용하면 2410개 레코드 중 2407개가 엉뚱한 자리에 떨어져,
스탯은 하나도 안 바뀌고 한글 대사 데이터가 스탯 값으로 덮어써진다.

```
0x736878B   원본패치가 쓰는 값: 1e 0f      한글판 그 자리: 63 81   ← 한글 대사 바이트
```

## 준비

이 레포에는 ISO 도, 패치 파일도, 밸런스 패치에 동봉된 변경목록(.ods) 도 두지
않는다 (`.gitignore`). 분석 도구와 문서만 담는다. 필요한 것:

```
한글패치 v2.4 ISO                       (각자 소유한 것)
SRWAPPlusVer1_2/APP 1_2.ppf             (Super Rebalance Wars Team 배포본)
SRWAPPlusVer1_2/Extras/SRW_APPlus_AllyChangelist.ods
```

검증에 쓰는 `units.json` 은 변경목록에서 뽑아 만든다.

```
python3 parse_ods.py "<...>/Extras/SRW_APPlus_AllyChangelist.ods" units.json
```

변경사항 문서(`CHANGES.md`) 도 생성물이다. 유닛 스탯·개조 단계·능력·무기·파일럿
정신기·SP·스킬까지 **바뀐 항목 전부**를 표로 뽑고, 유닛 스탯은 패치 ISO 와 직접
대조해 문서와 어긋나는 항목을 따로 표시한다.

```
python3 make_changes_md.py "<...>/SRW_APPlus_AllyChangelist.ods" \
        "<원본ISO>" "<패치ISO>" CHANGES.md
```

## 쓰는 법

```
python3 port_applus.py --iso "<한글판 v2.4>.iso" --ppf "APP 1_2.ppf" \
                       --out "<출력>.iso" [--emit-ppf APPlus1.2_KRv2.4.ppf]
```

`--out` 없이 실행하면 적용 없이 대상 ISO 검사만 한다.
적용 후에는 되읽기 + 내용 검증 9항목을 자동으로 돌리고, 하나라도 실패하면
0이 아닌 코드로 끝난다.

이미 만들어 둔 `APPlus1.2_KRv2.4.ppf` 를 일반 PPF 패처(Multi-Patch, PPF-O-Matic,
Rom Patcher JS)로 적용해도 결과는 같다. 이 PPF 는 원본과 달리 **blockcheck 을
켜 두었으므로 엉뚱한 ISO 에 적용하면 패처가 거부한다.**

## 매핑 근거

패치가 건드리는 데이터는 전부 한 덩어리(영문 `0x73534F0`~`0x7368790`)에 있고,
그 안에 세 테이블이 연속으로 놓여 있다. 세 테이블 모두 **하나의 델타
`+0x14E2F800`** 으로 한글판 `shared.bin` 에 정렬된다.

| 테이블 | 구조 | 영문 | 한글 | 패치 쓰기 |
|---|---|---|---|---|
| 유닛 | 305개 × `0x68` | `0x73534F0` | `0x1C182CF0` | 657 |
| `Weapxx` 무기 | 1101개 × `0x1C` | `0x735B0E4` | `0x1C18A8E4` | 1368 |
| `PTbl` 파일럿 | `0xC8` 간격 | `0x7362950` | `0x1C192150` | 379 |

### 유닛 레코드 (`0x68` = 104바이트)

| 오프셋 | 필드 |
|---|---|
| `+0x00` | HP (u16) |
| `+0x08` | 개조 단계 4개 (니블, HP/EN/운동성/장갑 순, 리틀엔디언) |
| `+0x1C` | EN (u16) |
| `+0x1E` | 장갑 (u16) |
| `+0x28~` | 무기 ID 목록 (u16 배열, `FFFF` 종료) |
| `+0x5C` | 이동력 |
| `+0x5D` | 운동성 |

인덱스 0 = Gundam RX-78 로 확인:

```
한글판 원본  HP 3500  개조 10/10/13/10  EN 80  장갑 1000  이동 5  운동성 85
패치 적용후  HP 4000  개조  7/ 8/ 8/ 6  EN 95  장갑 1200  이동 5  운동성 95
ODS AP Plus  HP 4000  개조  7/ 8/ 8/ 6  EN 95  장갑 1200  이동 5  운동성 95
```

### 무기 레코드 (`0x1C` = 28바이트)

`+0x06` 파워 / `+0x08` 명중 / `+0x0A` 크리티컬 / `+0x14` 탄수.
무기 ID 1 = RX-78 60mm 발칸: 파워 1500→**1700**, 명중 30→**50** (ODS 일치).

### 파일럿 레코드 (`0xC8` = 200바이트)

라미아 로브레스 레코드에서 세 필드가 독립적으로 확인된다.

| 필드 | 한글판 원본 | 패치 후 | ODS AP Plus |
|---|---|---|---|
| 정신기 ID | `04 07 05` (Accel/Focus/Alert) | `09 0c 1d` | Strike/Guard/Assail |
| SP 소모 | `05 0f 0a` (5/15/10) | `0f 14 0f` (15/20/15) | 15/20/15 |
| 기본 SP | `23` (35) | `3c` (60) | 60 |

원본 패치 readme 의 검증 지표 — "라미아로 새 게임을 시작해서 첫 정신기가
Strike 면 성공" — 과 일치한다.

## 사본 두 개를 모두 쓴다

한글판 ISO 는 같은 데이터를 두 벌 갖고 있다.

```
shared.bin  0x1C182CF0  (ISO9660 상 /PSP_GAME/USRDIR/shared.bin 안)
dummy.bin   0x0753CCF0  (= shared 위치 - 0x14C46000)
```

`BOOT.BIN` 에 `%s/sce_lbn0x%x_size0x%x` 포맷 문자열이 있다. 게임은 파일명이
아니라 **절대 LBA 로** 데이터를 읽으므로 어느 사본이 로드되는지 파일 이름만
보고는 알 수 없다. 패치 범위 87,136바이트에서 두 사본은 바이트 단위로
동일하므로, 안전하게 **양쪽 모두** 같은 값을 쓴다.

## 건너뛴 레코드 6개

| 오프셋 | 크기 | 이유 |
|---|---|---|
| `0x00C954` | 6B | ISO9660 디렉터리 레코드의 타임스탬프 (2017-05-21 → 2024-07-30). 게임 데이터가 아니다. 원본 패치가 다른 ISO 빌드에서 뜬 diff 라는 방증. |
| `0x6E5EAC8`~`0x6E5EB28` | 7B | Aestivalis Lunar Frame 유닛 레코드의 잉여 사본. 메인 테이블 인덱스 231 / 285~289 가 **같은 값**(`5014` `5668` `e6` `e2` `+0x60=17`)으로 이미 갱신되므로 게임 동작에 차이가 없다. 한글판 ISO 에는 대응 위치가 존재하지 않는다. |

나머지 2404개는 전부 이식되며, 두 사본에 쓰므로 실제 기록은 4808곳 /
7646바이트다.

## 검증

`verify.py` 는 `port_applus.py` 의 매핑 로직을 쓰지 않고 다른 경로로 확인한다.

```
python3 verify.py <원본ISO> <결과ISO> APPlus1.2_KRv2.4.ppf units.json
```

결과:

```
1) 원본 vs 결과 전체 바이너리 비교
   변경된 바이트 7646 — shared 3823 / dummy 사본 3823 / 그 밖 0
   패치 후에도 두 사본 일치 (불일치 0바이트)

2) 결과 ISO 스탯 vs ODS 변경목록
   유일 식별된 유닛 376필드 — 일치 372 / 문서차이 4 / 불일치 0

3) 생성된 PPF 를 독립 구현으로 재적용
   blockcheck 1024B 가 원본 ISO 0x9320 과 일치
   PPF 값 != 결과 ISO : 0바이트
   결과엔 바뀌었는데 PPF 에 없는 바이트 : 0
```

### ODS 문서차이 4건

`Extras/SRW_APPlus_AllyChangelist.ods` 는 2024-04, 패치 본체는 2024-08(v1.2)
이라 문서가 옛날 값을 담고 있다. **패치 본체가 기준**이고, 결과 ISO 는 원본
영문 패치와 동일하게 동작한다.

| 유닛 | 필드 | 원본 | ODS 기재 | 실제 패치 결과 |
|---|---|---|---|---|
| Altron Gundam | 장갑 | 1600 | 1500 | 1650 |
| Getter-3 | 운동성 | 60 | 65 | 60 (변경 없음) |
| Cardboardier V | 운동성 | 80 | 85 | 80 (변경 없음) |
| Vysaga | EN | 150 | 170 | 190 |

## 적용 확인 (실기)

라미아를 주인공으로 새 게임을 시작하면 아래가 보인다. 실기에서 확인했다.

| 확인 항목 | 원본 | 패치 후 |
|---|---|---|
| Lv1 정신기 1번 | 가속 (Accel) | **필중 (Strike)** |
| Lv1 정신기 2번 | 집중 (Focus) | **철벽 (Guard)** |
| 표시 SP (시작 시점) | 38 | **63** |

표시 SP 는 테이블의 기본 SP (35 → 60) 에 레벨 성장분이 더해진 값이다.

Axel Almer 를 고르면 이 확인법은 못 쓴다. Axel 의 1번 정신기는 패치 후에도
가속(Accel) 그대로다. 대신 **기본 SP 35 → 55** 를 보면 된다.

## 알아둘 것

  New Game 때 초기화되므로 기존 세이브나 New Game+ 로는 스킬 변경이 반영되지
  않는다.
